Implementation Guide: Video and PDF Document Uploads

Currently, the backend supports `ModuleType` of `TEXT`, `VIDEO`, and `CODE`, but it relies on storing strings (like text content or external video URLs) in the `body` field of the `Module` model. There is no direct file upload system implemented yet.

To build a robust course content builder that supports uploading actual video files and PDFs, follow these steps:

Phase 1: Backend Infrastructure (Storage & Routing)

1. Set up Cloud Storage:
   - Do NOT store large video or PDF files directly in the PostgreSQL database or the local server filesystem.
   - Set up an AWS S3 bucket, Cloudinary, or a local MinIO instance.
   - Get your API keys (Access Key, Secret Key, Region, Bucket Name) and add them to the backend `.env` file.

2. Install Upload Dependencies:
   - Run `npm install multer multer-s3 @aws-sdk/client-s3` in the `backend` directory.

3. Configure Multer Middleware:
   - Create `backend/src/middleware/upload.middleware.js`.
   - Configure the AWS SDK v3 client.
   - Set up two separate Multer configurations:
     - `videoUpload`: Filter for `video/mp4`, `video/webm`, etc. Set a large file size limit (e.g., 500MB).
     - `documentUpload`: Filter for `application/pdf`. Set a smaller limit (e.g., 20MB).

4. Create Upload Endpoints:
   - Create `backend/src/upload/upload.routes.js`.
   - Create two POST routes:
     - `POST /api/upload/video` (protected, uses `videoUpload.single('file')`)
     - `POST /api/upload/document` (protected, uses `documentUpload.single('file')`)
   - The controller for these routes should simply return the generated public URL of the uploaded file (e.g., `res.json({ url: req.file.location })`).

Phase 2: Database Schema Updates

1. Update `ModuleType` Enum (Optional but recommended):
   - You already have `TEXT`, `VIDEO`, `CODE`. Add `DOCUMENT` or `PDF` to `schema.prisma`.
   - Run `npx prisma migrate dev --name add_document_type`.

2. Handling the `body` field:
   - If `contentType` is `VIDEO` or `DOCUMENT`, the `body` field will now store the URL string returned from the S3 upload endpoint.

Phase 3: Frontend Implementation (The Course Builder)

1. Add UI for Uploading:
   - In your frontend Module Builder component (to be built), when a user selects "Add Video" or "Add PDF", render a file input (`<input type="file" accept="video/mp4,video/x-m4v,video/*" />`).

2. Upload Logic:
   - When a file is selected, show a loading spinner/progress bar.
   - Use Axios to POST the file to `/api/upload/video` using `FormData`.
   - Receive the `url` from the backend response.

3. Save Module:
   - Once the upload completes, take the received `url` and save the new Module to the database (`POST /api/courses/:courseId/modules`) where `contentType: 'VIDEO'` and `body: uploadedUrl`.

4. Rendering Content (Course Player):
   - In `CoursePlayer.jsx`, when rendering the current module:
     - If `contentType === 'VIDEO'`, render a standard `<video controls src={module.body} />` tag or use a specialized player like `video.js` or `react-player`.
     - If `contentType === 'DOCUMENT'`, render an iframe or a dedicated PDF viewer component (like `react-pdf`) pointing to the URL stored in `module.body`.

Security Considerations:
- If courses are paid, files stored in S3 shouldn't be completely public. You may need to implement "Signed URLs" in the backend to stream videos securely so that only enrolled students can view the direct file links.
